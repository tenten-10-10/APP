# Ship an iOS app to TestFlight (GitHub Actions + fastlane)

A validated pipeline: **push (or tag) → GitHub macOS runner → fastlane archives,
exports with automatic cloud signing, uploads to TestFlight.** No certificates or
provisioning profiles to manage locally — an App Store Connect API key does it.

Works the same whether you drive it from **Claude Code**, **chat (claude.ai)**, or
delegate the Apple-portal browser steps to **Cowork**.

> Reference values from the project this was distilled from (replace with yours):
> app `ProjectStock.xcodeproj`, scheme `ProjectStock`, bundle id
> `com.tenten.tanamiru`, display name タナミル.

## Phase 0 — Prerequisites
- Apple Developer Program membership (paid).
- A GitHub repo for the app.
- The app builds to a **shared scheme** (`<App>.xcodeproj/xcshareddata/xcschemes/<Scheme>.xcscheme` committed).
- You do NOT need a Mac for CI (GitHub's `macos-latest` runner builds). A Mac is
  only handy for local `fastlane beta` runs.

## Phase 1 — Apple / App Store Connect setup (browser; delegatable to Cowork)
1. **Developer portal → Identifiers → App IDs**: register an explicit Bundle ID
   (`com.you.yourapp`). Enable capabilities you use (e.g. **iCloud → CloudKit**,
   **Push Notifications**). If using CloudKit, create container
   `iCloud.com.you.yourapp` and assign it.
2. **App Store Connect → My Apps → +**: create the app record (platform iOS,
   name, primary language, the Bundle ID, an SKU).
3. **App Store Connect → Users and Access → Integrations → App Store Connect API
   → Team Keys → Generate**:
   - **Role = Admin.**  ⚠️ *This is the #1 gotcha.* An **App Manager** key can
     upload builds but **cannot create the distribution signing assets**, so the
     export step fails with `exportArchive Cloud signing permission error`.
   - Download the `.p8` (one time only). Note the **Key ID** and **Issuer ID**.
4. Get your **Team ID** (Developer portal → Membership, 10 chars).

## Phase 2 — GitHub repository secrets
Settings → Secrets and variables → Actions → New repository secret:

| Secret | Value |
|---|---|
| `ASC_KEY_ID` | the API Key ID |
| `ASC_ISSUER_ID` | the API Issuer ID |
| `ASC_KEY_P8_BASE64` | `base64 -i AuthKey_XXXX.p8` (the whole .p8, base64) |
| `APP_STORE_TEAM_ID` | your 10-char Team ID |

> macOS: `base64 -i AuthKey_XXXX.p8 | pbcopy` then paste.

## Phase 3 — Repo files (the validated working set)

### `Gemfile`
```ruby
source "https://rubygems.org"
gem "fastlane"
```
**Do NOT commit a `Gemfile.lock` generated by macOS system Ruby** (it pins bundler
1.17.2, which crashes on the runner's Ruby 3.3 with `undefined method 'untaint'`).
The workflow runs `rm -f Gemfile.lock` before `bundle install` to be safe.

### `fastlane/Appfile`
```ruby
app_identifier("com.you.yourapp")
```

### `fastlane/Fastfile`  ← the exact working lane
```ruby
default_platform(:ios)

PROJECT = "YourApp.xcodeproj"
SCHEME  = "YourApp"
APP_ID  = "com.you.yourapp"

platform :ios do
  desc "Build and upload a new build to TestFlight"
  lane :beta do
    api_key = app_store_connect_api_key(
      key_id:       ENV.fetch("ASC_KEY_ID"),
      issuer_id:    ENV.fetch("ASC_ISSUER_ID"),
      key_filepath: ENV.fetch("ASC_KEY_PATH")
    )

    team_id = ENV.fetch("APP_STORE_TEAM_ID")

    # Next build number = highest already on TestFlight + 1, passed via xcargs so
    # no project file is mutated (works without agvtool/versioning system).
    next_build = latest_testflight_build_number(
      api_key:        api_key,
      app_identifier: APP_ID,
      initial_build_number: 0
    ) + 1

    build_app(
      project:          PROJECT,
      scheme:           SCHEME,
      configuration:    "Release",
      export_method:    "app-store",
      output_directory: "build",
      clean:            true,
      # Make the export step do automatic cloud signing (creates the app-store
      # distribution profile via the Admin API key).
      export_options: {
        signingStyle: "automatic",
        teamID:       team_id
      },
      # API-key auth for xcodebuild. gym appends `xcargs` to BOTH the archive and
      # the export invocations — so DO NOT also set `export_xcargs` with the same
      # -authenticationKey* flags (that duplicates them → xcodebuild exit 64).
      # Do NOT wrap the .p8 path in quotes (passed literally to the export step).
      xcargs: [
        "-allowProvisioningUpdates",
        "-authenticationKeyPath", ENV.fetch("ASC_KEY_PATH"),
        "-authenticationKeyID", ENV.fetch("ASC_KEY_ID"),
        "-authenticationKeyIssuerID", ENV.fetch("ASC_ISSUER_ID"),
        "DEVELOPMENT_TEAM=#{team_id}",
        "CURRENT_PROJECT_VERSION=#{next_build}"
      ].join(" ")
    )

    upload_to_testflight(
      api_key:                          api_key,
      skip_waiting_for_build_processing: true,
      distribute_external:              false
    )

    UI.success("Uploaded build #{next_build} to TestFlight 🚀")
  end
end
```

### `.github/workflows/testflight.yml`
```yaml
name: TestFlight
on:
  workflow_dispatch:        # manual: Actions → TestFlight → Run workflow
  push:
    tags: ["v*"]            # release tags (e.g. v1.0.0) → TestFlight
concurrency:
  group: testflight-${{ github.ref }}
  cancel-in-progress: false
jobs:
  beta:
    runs-on: macos-latest
    timeout-minutes: 45
    steps:
      - uses: actions/checkout@v4
      - uses: maxim-lobanov/setup-xcode@v1
        with:
          xcode-version: latest-stable

      # (Only if your project is generated from a script / xcconfig.)
      - name: Generate Xcode project
        run: python3 Scripts/generate_pbxproj.py

      - name: Write App Store Connect API key (.p8)
        env:
          ASC_KEY_P8_BASE64: ${{ secrets.ASC_KEY_P8_BASE64 }}
          ASC_KEY_ID: ${{ secrets.ASC_KEY_ID }}
        run: |
          mkdir -p "$HOME/private_keys"
          echo "$ASC_KEY_P8_BASE64" | base64 --decode > "$HOME/private_keys/AuthKey_${ASC_KEY_ID}.p8"

      - name: Write fastlane/.env
        env:
          ASC_KEY_ID: ${{ secrets.ASC_KEY_ID }}
          ASC_ISSUER_ID: ${{ secrets.ASC_ISSUER_ID }}
          APP_STORE_TEAM_ID: ${{ secrets.APP_STORE_TEAM_ID }}
        run: |
          cat > fastlane/.env <<EOF
          ASC_KEY_ID=${ASC_KEY_ID}
          ASC_ISSUER_ID=${ASC_ISSUER_ID}
          ASC_KEY_PATH=${HOME}/private_keys/AuthKey_${ASC_KEY_ID}.p8
          APP_STORE_TEAM_ID=${APP_STORE_TEAM_ID}
          EOF

      - name: Install Ruby dependencies
        run: |
          rm -f Gemfile.lock
          bundle install

      - name: Build & upload to TestFlight
        run: bundle exec fastlane beta
```

## Phase 4 — Run it
- **Manual:** Actions tab → *TestFlight* → **Run workflow**.
- **Release:** `git tag v1.0.0 && git push origin v1.0.0`.
- Result: archive → export (automatic cloud signing) → upload. The build appears
  in App Store Connect → TestFlight after Apple finishes processing (a few min).
  Answer export-compliance "No" if you set `ITSAppUsesNonExemptEncryption=false`.

## CloudKit (only if the app uses it)
TestFlight builds use the **Production** CloudKit environment. Run the app once on
a device/simulator (Debug) so the schema is created in Development, then in
CloudKit Console choose **Deploy Schema Changes to Production**, or sync fails for
testers. Use a Release entitlements file with `aps-environment = production`.

## Troubleshooting — real failures from building this pipeline, and the fix

| Symptom (CI log) | Cause | Fix |
|---|---|---|
| `bundler ... lockfile was generated with 1.17.2` → `undefined method 'untaint'` | Committed `Gemfile.lock` from macOS system Ruby pins ancient bundler; incompatible with runner Ruby 3.3 | `rm -f Gemfile.lock` before `bundle install` (or don't commit it / pin a modern bundler) |
| `cannot find type 'NSManagedObjectID' in scope` (ARCHIVE FAILED) | A Swift file uses Core Data types but only `import SwiftUI` | Add `import CoreData` to that file |
| `No Accounts: Add a new account in Accounts settings` during build | `-allowProvisioningUpdates` fell back to Xcode "Accounts" (none on CI) | Pass the API key to xcodebuild: `-authenticationKeyPath/-authenticationKeyID/-authenticationKeyIssuerID` (via `xcargs`) |
| `exportArchive Cloud signing permission error` / `No profiles for '<bundle id>' were found` (exit 70) | API key role is **App Manager** — can upload but not create signing assets | Regenerate the API key with the **Admin** role; update `ASC_KEY_*` secrets |
| `xcodebuild` prints its full usage and exits **64** during export | Duplicate `-authenticationKeyPath` — `export_xcargs` repeated flags gym already appends from `xcargs` | Keep auth only in `xcargs`; remove `export_xcargs`. Use `export_options { signingStyle: "automatic", teamID }` for explicit export signing |
| `Could not find option 'api_key' in the list of available options` for `build_app` | `api_key:` is a `pilot`/`deliver` option, not a `gym` one | Don't pass `api_key:` to `build_app`; authenticate via the `xcargs` auth flags above |

## Reuse across Claude surfaces
- **Claude Code (this & other repos):** copy this folder to `~/.claude/skills/`
  to make it available in every project, then invoke `/ship-ios-to-testflight`.
  Keeping it in the repo's `.claude/skills/` scopes it to this project.
- **Chat (claude.ai):** open this `SKILL.md` and paste/follow the relevant phase.
- **Cowork (browser):** the Phase 1 Apple-portal steps are scripted for a browser
  agent in `docs/COWORK_APPSTORE_SETUP.md` and `docs/COWORK_TESTFLIGHT.md` —
  hand those to Cowork to register the App ID, container, app record, and the
  **Admin** API key, then report the values back for the GitHub secrets.
